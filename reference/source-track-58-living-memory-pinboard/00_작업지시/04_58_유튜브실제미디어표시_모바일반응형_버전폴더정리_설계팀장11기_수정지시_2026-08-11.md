# 1. 현재 확인된 실제 문제

현재 V1.1은 YouTube URL을 파싱하고 `videoId`를 얻는 로직은 존재한다.

하지만 화면에 실제 YouTube 썸네일을 사용하는 대신,
videoId를 표시하는 **offline-safe SVG preview**를 기본 이미지로 사용하고 있다.

또한 Viewer에서도 YouTube Moment를 열었을 때 실제 YouTube player를 띄우지 않고
다시 preview image만 표시하는 구조다.

따라서 기존 보고의:

- YouTube URL 3/3 PASS
- Live Preview PASS

는 **URL parsing 기준 PASS**일 뿐,
제품 오너가 기대한:

- 실제 썸네일 표시
- 실제 YouTube 영상 재생

기준으로는 미완료다.

# 3. YouTube 실제 썸네일 표시 — HARD REQUIREMENT

## 3-1. 지원 URL

최소 아래 3개는 모두 지원한다.

- `https://www.youtube.com/watch?v=VIDEO_ID`
- `https://youtu.be/VIDEO_ID`
- `https://www.youtube.com/shorts/VIDEO_ID`

URL 입력 즉시 `videoId`를 추출한다.

---

## 3-2. 실제 썸네일 우선

정상 네트워크 환경에서는 실제 YouTube thumbnail을 사용한다.

우선 순서 예시:

1. `https://i.ytimg.com/vi/{VIDEO_ID}/maxresdefault.jpg`
2. 실패 시 `https://i.ytimg.com/vi/{VIDEO_ID}/hqdefault.jpg`
3. 실패 시 현재 offline-safe fallback SVG

중요:

**fallback SVG가 기본값이면 안 된다.**

반드시:

**실제 YouTube 썸네일 → 실패 시 fallback**

순서여야 한다.

---

## 3-3. 적용 위치

실제 썸네일은 아래 모두 동일하게 동기화되어야 한다.

- 새 Moment Composer Live Preview
- 기존 Moment Edit Live Preview
- Board Card
- Detail
- Viewer 진입 전 poster
- Cinema 대상 데이터

---

## 3-4. Loading / Error 상태

썸네일을 불러오는 동안:

`YouTube 미리보기를 불러오는 중`

표시를 제공한다.

실패하면 깨진 이미지 아이콘을 그대로 노출하지 말고:

`미리보기를 불러오지 못했어요`

+ offline-safe fallback을 사용한다.

# 4. 실제 YouTube 영상 재생 — HARD REQUIREMENT

## 현재 문제

현재 YouTube Moment의 Viewer가 실제 동영상을 재생하지 않고 preview image만 보여준다.

이 상태는 FAIL이다.

## 수정

`Moment 열기` / `재생` 실행 시 실제 YouTube embed player를 사용한다.

예:

`https://www.youtube.com/embed/{VIDEO_ID}`

가능하면:

- `playsinline=1`
- 적절한 fullscreen 허용
- 모바일 inline playback 대응

을 적용한다.

---

## 4-1. iframe 실패 대응

브라우저 정책, 영상 소유자 embed 제한 등으로 재생이 실패할 수 있다.

이 경우 UI에 명확히:

`이 영상은 여기서 바로 재생할 수 없어요.`

그리고:

`YouTube에서 재생`

버튼을 제공한다.

해당 버튼은 사용자가 저장한 실제 원본 URL을 연다.

절대로 재생 실패를 성공처럼 위장하지 않는다.
