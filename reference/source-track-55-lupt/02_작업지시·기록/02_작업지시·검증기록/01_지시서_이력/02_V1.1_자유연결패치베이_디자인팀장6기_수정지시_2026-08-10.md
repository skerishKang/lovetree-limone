# 0. 제품 오너 최신 피드백 — 최우선

V1의 다음 요소는 좋았으므로 **반드시 보존**한다.

- Moment node 자체를 드래그하면 연결선이 실시간으로 따라오는 것
- LUPT를 움직이면 bundle과 bend가 같이 움직이는 것
- 가운데 작은 흰색 LUPT core가 빛나는 것
- 선택한 Connection을 LUPT가 실제 path를 따라가는 것
- “내가 이 영상을 보고 그 다음 영상을 봤다”는 순서를 빛의 이동으로 보여주는 것
- 자동 routing / path finding의 신기함
- 현재 violet / cyan / rose 계열의 발광 색감
- Track 53에서 가져온 `getTotalLength()`, `getPointAtLength()`, hot tip, fading trail, arrival reaction, ResizeObserver 계열 엔진

그러나 V1은 다음이 부족하다.

1. **Connection이 이미 짜여 있어서 사용자가 직접 연결을 만들 수 없다.**
2. 노드 양쪽 port가 장식처럼 보이고 실제 자유 연결의 출발점이 아니다.
3. 한 Moment에서 한 개뿐 아니라 두 개, 세 개, 여러 개의 다음 Moment로 자유롭게 연결하고 싶다.
4. 여러 Moment가 하나의 Moment로 모이는 연결도 가능해야 한다.
5. 참고영상처럼 **노드뿐 아니라 선 자체도 사용자가 직접 만들고 재배선할 수 있어야 한다.**
6. V1의 전체 시각문법이 Track 53과 너무 비슷하다.
7. serif / Georgia / 명조 계열 타이포그래피를 제거하고 완전히 다른 sans-serif 계열로 바꾼다.

이번 V1.1의 핵심은:

> **AUTO-ROUTED CONNECTION VIEW → USER-WIRABLE LIVING CONNECTION CANVAS**

로 발전시키는 것이다.

# 2. V1.1에서 가장 중요한 새 기능

## **사용자가 직접 선을 만든다.**

Moment node의 좌/우 port는 이제 장식이 아니다.

### Desktop 기본 조작

1. 사용자가 Moment A의 **OUT port**를 pointer down 한다.
2. 손가락/마우스를 움직이는 동안 임시 cable이 pointer를 따라온다.
3. 연결 가능한 Moment들의 **IN port**가 빛난다.
4. Moment B의 IN port 위에서 release.
5. 실제 Connection A → B 생성.
6. 생성 직후 cable은 routing engine에 들어가 자동으로 정돈된다.
7. relation input이 열린다.

예:
`WHY NEXT?`
- 웃는 표정이 더 궁금해서
- 이 무대를 보고 다른 직캠을 찾아서
- 댓글 추천을 따라가서
- 직접 입력

# 3. ONE-TO-MANY / MANY-TO-ONE

이번 작업에서 반드시 구현한다.

## ONE → MANY

하나의 Moment에서:

`Moment A`
→ `Moment B`
→ `Moment C`
→ `Moment D`

처럼 **같은 OUT port 또는 같은 output group에서 여러 Connection 생성 가능**.

한 개 연결했다고 port가 닫히면 FAIL.

### 시각
동일 source에서 여러 선이 출발하면:
- 처음에는 짧은 shared trunk를 사용할 수 있음
- 이후 목적지에 따라 fan-out
- 각 Connection identity 유지
- lane spacing 유지

---

## MANY → ONE

여러 Moment가 하나의 다음 Moment로 모일 수도 있어야 한다.

예:

`Performance`
`Interview`
`Funny Clip`
→ `결정적 입덕 Moment`

IN port는 여러 incoming connection을 받을 수 있다.

# 4. PORT 디자인

현재 V1의 양쪽 작은 원은 좋은 출발점이다.

이번에는 이것을 **실제 patch socket**으로 강화한다.

## 기본
- LEFT = IN
- RIGHT = OUT

### Idle
작은 ring만 보임.

### Hover / focus
ring 확장 + soft glow.

### Wiring 시작
source port가 강하게 점등.

### Valid target
연결 가능한 target port에 pulse.

### Invalid target
점등하지 않는다.

### Connected
선이 port 중심점에 정확히 닿아야 한다.

# 5. 한 node에서 여러 선이 생길 때 port 처리

무조건 작은 원을 5개 미리 늘어놓지 않는다.

기본은 하나의 compact socket으로 보이게 한다.

연결 수가 늘어나면 다음 중 하나를 사용한다.

## 권장 A — Dynamic Port Fan
hover 시:
- main socket 주변에 작은 sub-port 2~4개 fan-out
- 새 연결을 만들 때 빈 sub-port 선택

## 권장 B — Multi-Connection Hub
하나의 socket이 여러 edge를 받아들이고
선들이 출발 직후 자동 lane spacing.

### 권장
V1.1에서는 **B를 기본**으로 하고,
시각적으로 필요할 때만 작은 sub-port split을 보여라.

화면이 전문 엔지니어용 회로도처럼 복잡해지면 안 된다.

# 6. Connection 생성 후 자동 routing

사용자가 직선을 직접 정교하게 그릴 필요는 없다.

사용자는:
- source
- destination

만 정한다.

그다음 LUPT routing engine이:

- 다른 node 회피
- shared route 탐색
- bundle 합류
- lane spacing
- bend
- fan-out

을 자동 계산한다.

즉:

> **USER CHOOSES THE RELATION.  
> LUPT FINDS THE PATH.**

이것이 이 제품의 핵심이다.

# 7. 그러나 선도 수동으로 만질 수 있어야 한다

참고영상의 중요한 장점이다.

## V1.1 필수

Connection을 선택하면 cable 위에
`reroute handle / bend handle`을 표시한다.

사용자는 이 handle을 잡아 움직일 수 있다.

### 동작
- handle drag → path geometry live reflow
- source/destination endpoint 유지
- 주변 bundle도 필요하면 재배치
- manual handle을 AUTO TIDY가 무시하지 말고 가능한 범위에서 존중

### 추가
Desktop:
- Connection double click → reroute handle 추가

Mobile:
- Connection long press → handle 추가

최소 1개 manual reroute handle 추가/이동/삭제가 실제 동작해야 한다.

# 11. LUPT의 역할

현재 흰색 luminous core는 **보존**한다.

제품 오너가 이 부분을 좋게 평가했다.

다만 V1.1에서는 LUPT의 역할을 더 분명히 한다.

## LUPT = SMART ROUTER + PATH WALKER

### Mode 1 — ROUTE
새 Connection이 생기면 LUPT가 잠깐 source 근처에 나타나
새 route를 찾아준다.

### Mode 2 — TIDY
AUTO TIDY 시 bundle을 정리.

### Mode 3 — WALK
Connection 선택 시 실제 SVG path를 따라 이동.

### Mode 4 — JUNCTION
사용자가 LUPT를 드래그하면 shared route가 따라 움직임.

즉 흰 원은 단순 decorative orb가 아니라
**실제 Connection logic을 대표하는 살아 있는 cursor/agent**다.

최소 구조:

```js
moments = [
  { id, x, y, ... }
]

connections = [
  {
    id,
    sourceMomentId,
    sourcePort: "out",
    targetMomentId,
    targetPort: "in",
    relation,
    manualJunctions: []
  }
]
```

새 연결 생성 시 `connections` 배열에 실제 추가.

삭제 시 제거.

rewire 시 target/source ID 변경.
