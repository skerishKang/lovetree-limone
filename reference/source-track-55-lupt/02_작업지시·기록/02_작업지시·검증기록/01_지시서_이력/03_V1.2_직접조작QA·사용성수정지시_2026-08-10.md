# 2. 그런데 사용자가 “안 된다”고 느낄 수 있는 실제 원인

현재 V1.1은 자유 wiring처럼 보이지만 실제 gesture contract가 생각보다 엄격하다.

## 현재 허용
`RIGHT OUT → LEFT IN`

## 현재 허용하지 않음
- `LEFT IN → RIGHT OUT`
- `OUT → OUT`
- `IN → IN`
- 자기 자신 `OUT → 자기 IN`
- 이미 존재하는 동일 `A → B`를 다시 생성

특히 가장 큰 UX 문제:

> **왼쪽 IN 원에서 선을 잡아 시작하면 아무 일도 일어나지 않는다.**

사용자는 화면에 양쪽 원이 모두 보이기 때문에
“어느 원에서든 잡아서 다른 노드의 반대쪽 원에 꽂을 수 있다”고 자연스럽게 예상할 수 있다.

즉 V1.1의 엔진 QA는 통과했지만,
**사용자 자유도/발견성 QA는 충분하지 않았다.**

# 3. Drop precision 문제

현재 drag 완료 시 `document.elementFromPoint()`가 정확히 `.port.in` hit area를 잡아야 Connection이 생성된다.

Port button hit area 자체는 약 40px이지만,
사용자가 target Moment 카드의 가장자리나 `IN` 글자 주변에 놓으면 실패할 수 있다.

현재 실패 피드백은 작은 toast 중심이라
사용자가 “왜 안 됐는지” 즉시 이해하기 어렵다.

---

# 4. 연하게 보이는 색의 현재 코드 의미

현재 코드의 Connection fiber opacity:

- 기본 idle cable: `opacity: .57`
- 선택 cable: `opacity: 1`
- 다른 cable이 선택됐을 때 비선택 cable: `opacity: .18`
- invalid target port: `opacity: .35`
- completed memory trace: `opacity: .36`

즉 일부 색이 연한 것은 렌더링 오류가 아니라
**idle / non-selected / invalid / memory state를 opacity로 구분한 의도된 상태**다.

그러나 제품 오너가 의미를 바로 알아보지 못했다면 시각언어가 충분히 명확하지 않은 것이다.

# 5. V1.2 수정 핵심 — 양쪽 Socket을 실제로 사용할 수 있게 하라

## A. OUT에서 시작
기존 유지:

`Moment A OUT → Moment B IN`
= `A → B`

## B. IN에서 시작
신규 필수:

`Moment B IN → Moment A OUT`
로 역방향 drag해도
결과는 동일하게:

`A → B`

를 생성한다.

즉 사용자는 **양쪽 socket 어느 쪽에서든 cable을 잡을 수 있다.**

하지만 데이터 semantics는 계속:
- OUT = source
- IN = target

으로 보존한다.

### HARD REQUIREMENT
`IN → OUT` gesture가 실제로 작동해야 한다.

# 6. Card-edge Smart Snap

사용자가 target port의 작은 점에 픽셀 단위로 정확히 놓게 만들지 않는다.

V1.2에서는:

- OUT을 끌고 target Moment 카드의 왼쪽 25~36px 영역에 들어가면 IN으로 snap
- IN을 끌고 source Moment 카드의 오른쪽 25~36px 영역에 들어가면 OUT으로 snap

하도록 한다.

Target이 잡히면:
- port 확대
- magnetic halo
- cable tip snap animation

을 보여준다.

즉 **정확한 원 위에 놓는 방식 + 카드 가장자리 magnetic snap** 둘 다 지원한다.

---

# 7. Invalid gesture를 침묵시키지 마라

다음은 즉시 pointer 근처에서 이유를 보여준다.

### OUT → OUT
`CONNECT OUT TO IN`

### IN → IN
`CONNECT IN TO OUT`

### SELF
`SAME MOMENT CANNOT CONNECT TO ITSELF`

### DUPLICATE A → B
새 선을 만들지 말고 기존 Connection을 자동 선택하면서:
`THIS PATH ALREADY EXISTS`

그리고 Inspector에서 기존 WHY NEXT?를 보여준다.

작은 toast 하나만 뜨고 사라지는 방식으로 끝내지 않는다.

---

# 8. WALK 중 wiring

사용자가 LUPT WALK 애니메이션 중 port를 잡았을 때
조작이 무시되면 “가끔 연결이 안 된다”고 느낄 수 있다.

V1.2에서는 새 wiring gesture를 사용자 우선으로 처리한다.

권장:
- port pointerdown 시 현재 WALK token cancel
- LUPT를 home 또는 현재 위치에 안정화
- 즉시 wiring mode 진입

최소한 아무 반응 없이 return 하지 않는다.

# 9. 색상 가독성 수정

현재 palette 자체는 유지한다.

다만 opacity hierarchy를 조정한다.

권장:
- idle fiber: `.68 ~ .76`
- selected: `1`
- dimmed: `.32 ~ .42`
- completed memory trace: `.40 ~ .48`

비선택 connection이 `.18`까지 내려가 거의 사라지는 방식은 피한다.

선택은 “다른 것을 없애서” 표현하기보다
selected cable의:
- inner fiber brightness
- halo
- direction tip
- port glow

를 강화해서 표현한다.

# 10. 상태 Legend / 도움말

화면에 작고 닫을 수 있는 도움말을 추가한다.

예:

`HOW TO WIRE`
1. Grab either socket.
2. Drop on the opposite socket of another Moment.
3. LUPT finds the route.

작은 legend:
- Bright = selected path
- Colored = connected path
- Pulsing socket = valid target
- Gray socket = invalid target

제품 오너가 색 의미를 질문해야만 이해되는 상태면 부족하다.

# 11. 기존 one-to-many / many-to-one은 반드시 보존

V1.2 수정 과정에서 regression 금지.

한 Moment에서 여러 다음 Moment:
`A → B / C / D / E ...`

여러 Moment에서 하나의 target:
`A / B / C / D → E`

모두 계속 가능해야 한다.

---

# 12. 동일 A → B 다중 edge 정책

V1.2에서도 기본적으로 동일 source/target pair의 완전 중복 edge는 1개만 유지한다.

대신 중복 시 기존 edge를 선택하고 WHY NEXT?를 편집하게 한다.

이 정책은 화면의 cable 중복을 방지하기 위한 현재 제안이며,
제품 오너가 추후 동일 두 Moment 사이 복수 relation을 원하면 별도 확장한다.
