# LoveTree 49 — 제작과정 실수·교훈 인수인계

## 이 문서의 목적

49는 최종 화면만 보면 과정상의 핵심 실패 원인을 알기 어렵다. 차기 설계팀장/디자인팀장이 같은 실수를 반복하지 않도록 기록한다.

## 1. 자산이 충분한데도 계속 생성한 문제

초기에는 고화질 dynamic shot을 더 만들라는 지시가 이어져 storyboard 폴더에 자산이 과도하게 쌓였다. 제품 오너는 “이제 사진을 그만 만들고 기존 자산을 잘 섞어 편집하라”고 명확히 정정했다.

**교훈:** asset warehouse가 충분하면 generation gate를 즉시 닫고 assembly/editing으로 전환한다.

## 2. Storyboard가 좋은데 구현에서 다시 해석한 문제

49는 storyboard 자체의 품질은 계속 좋았지만 구현에서 portrait strip, static card, generic portal 등으로 다시 해석되며 품질이 떨어졌다.

**교훈:** 제품 오너가 storyboard exact reproduction을 요구하면 storyboard를 “영감”이 아니라 spec으로 다룬다.

## 3. Codex와 비슷해진 문제

고화질 정지 이미지 + 느린 scene scale/fade 중심으로 가면 Codex cinematic homepage와 비슷해진다.

49의 차별점은 **cut-led aggressive teaser / irregular microcut / impact frame / interactive Save-Connection**이다.

## 4. SAVE가 자동 통과된 문제

Save는 서사 문구가 아니라 실제 사용자 행동 Gate여야 한다.

**교훈:** LOVE TREE의 의미를 구현할 때 클릭/상태 변화가 실제로 있어야 한다.

## 5. Tree Visual Master 처리 오류

제품 오너가 직접 승인한 Tree 이미지를 줬는데, “같은 형태를 motion-capable로 재구성”하라는 지시가 들어가 procedural Tree가 다시 만들어졌다.

**교훈:** approved exact asset 단계에서는 ‘재구성/재해석’ 금지. Exact-use인지 reference-use인지 지시서에 명시한다.

## 6. 기술 QA가 미학을 대체한 문제

가지 개수, endpoint 오차 0.016px 같은 수치는 정렬 정확도는 증명하지만 Tree가 아름다운지는 증명하지 않는다.

**교훈:** Visual Gate는 제품 오너 승인 이미지와 actual screenshot side-by-side가 최우선이다.

## 7. Standalone broken media

단일 HTML은 portability가 핵심이다. 처음엔 보이다가 Tree state에서 엑박이 뜨는 것은 완전 FAIL이다.

**교훈:** asset preload + state transition source consistency + video→poster→embedded fallback을 둔다.

## 8. 현재 49의 독립 역할

49는 LoveTree 전체 제품의 단일 정답이 아니다. 다양한 LoveTree 시각 템플릿 중 **Superhuman cyber-cinematic interactive teaser** 계열 후보로 보존한다.

차기 담당자는 49를 전체 제품 기본 UI로 확대 적용하지 말고, 승인받은 부분만 재사용한다.
