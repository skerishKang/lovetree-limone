# Track 57 V1.2 — YouTube Live Thumbnail Sync QA

## Status
PASS — candidate for product owner review.

## Defect reproduced
V1.1 changed `sourceUrl/mediaUrl`, but did not update `thumbnailUrl` or the actual Living Glass Card image after saving a new YouTube URL.

## Baseline comparison
`01_러브트리_첫여정통합_v1.html` was inspected directly. Its behavior is:

`input event → youtubeId(url) → https://img.youtube.com/vi/{ID}/hqdefault.jpg → immediate preview`

Track 57 V1.2 now uses the same thumbnail derivation contract without redesigning the card.

## Same-URL Side-by-Side
Test URL:
`https://www.youtube.com/watch?v=hmE9f-TEutc`

Expected thumbnail request:
`https://img.youtube.com/vi/hmE9f-TEutc/hqdefault.jpg`

Results:
- First Journey preview generated the exact expected URL: PASS
- V1.2 edit Live Preview generated the exact expected URL before save: PASS
- Saving updated `Moment.thumbnailUrl`: PASS
- Saving updated the actual Living Glass Card `<img>`: PASS
- Detail image updated to the same thumbnail: PASS

### Managed Chromium network note
The managed QA Chromium cannot load external `img.youtube.com` pixels directly. For visual differential QA only, the exact `img.youtube.com` requests from BOTH pages were intercepted and fulfilled with the same local image fixture. The request URL was not rewritten. This verifies that the two implementations derive and render the same thumbnail request and that V1.2 is no longer blank because of stale internal `thumbnailUrl` state. Product-owner browser verification remains the final external-network check.
