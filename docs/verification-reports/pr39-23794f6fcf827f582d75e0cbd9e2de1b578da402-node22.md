## 4. 발견 사항

**F4 — 기존 테스트 3건이 새 head에서 실패 (신규 회귀)**
- `tests/moment-data-spine.test.mjs`의 "negative/decimal/string sortOrder is rejected by validation"이 **이전 head(7d53480)에서는 통과 → 새 head(23794f6)에서 실패**로 전환 (직접 재실행으로 확인).
- 원인: 새 head가 `MEMORY_CONTENT_RULES`에서 sortOrder를 제거하고 create 규칙이 클라이언트 sortOrder를 더 이상 검증하지 않음(서버 권위 설계). `validate()`는 규칙에 없는 키를 무시(스트립)하므로 `sortOrder: -1/1.5/"abc"`가 400 없이 통과 → 201 반환.
- 기존 테스트가 설계 변경에 미갱신된 **스테일 테스트**. 코드 동작 자체는 의도된 설계(클라이언트 sortOrder 무시, 서버 계산)와 일치. 테스트는 "ignored"(서버 계산 검증)로 갱신하거나, 400 거부를 유지하려면 create 규칙에 sortOrder를 남겨야 함.
- 영향: 빌드/타입체크는 통과하지만 **PR 자체 테스트 스위트가 green하지 않음** — 비차단 발견.

**F5 — 서로 다른 clientKey 동시 삽입(Promise.all) 테스트 부재**
- 신규 타겟 테스트에 동시성(concurrent/`Promise.all`) 케이스가 없음. UNIQUE+retry 설계의 실질 핵심인 동시 append 경합은 유닛 수준에서 검증되지 않음. (retry/409는 시뮬레이션으로 검증됨)
- 비차단 커버리지 갭.
