# LoveTree 16개 HTML + 현재 TSX 통합 사용자 여정 분석

작성 기준: 2026-08-01

분석 범위

- 업로드된 독립 HTML 16개 전체
- GitHub `skerishKang/lovetree-limone`의 현재 `main`
- 공개된 Preview 주소의 소스 대응 검토
- 코드 수정·배포는 수행하지 않음

---

## 1. 결론

16개 HTML은 같은 제품의 경쟁 시안이라기보다, LoveTree가 필요로 하는 서로 다른 **제품 단계와 보기 방식**을 각각 구현한 모듈 집합이다.

- `complete-manga-refinement`는 브랜드 랜딩과 첫 트리 진입
- `step2-emotion-refined`는 첫 순간의 감정·문장 기록
- `step3-connect-next-video`는 두 번째 순간과 관계 연결
- `growing-tree-v6`는 일상적인 트리 성장·편집 작업공간
- `node-graph-prototype`은 고급 연결 그래프 편집
- `timeline`, `person albums`, `vertical album`은 동일 데이터를 다르게 소비하는 보기 모드
- `community-discovery-v2`는 공개 탐색과 빠른 미리보기
- `300 finale`, `aurora`, `rainbow canopy`, `purple bloom`은 특정 성장 구간의 축하·회고 시각화

현재 TSX는 인증, API, 서버 저장, 트리·순간 CRUD, 내 트리, 공개 트리라는 제품 기반은 가장 강하다. 반면 첫 사용자 여정은 HTML보다 입력 정보와 감정적 연출이 축소되었고, 성장 트리는 8개 고정 배치에 가깝다. 따라서 공식 제품은 **TSX의 인프라를 유지하되 HTML들의 강점을 단계별로 재배치**해야 한다.

공식 기준은 다음과 같다.

1. 랜딩은 `complete-manga-refinement` 계열의 따뜻한 종이·식물 톤을 유지한다.
2. 첫 트리 생성은 이름만 받고 종료하지 않고, 발견 → 마음 → 연결 → 첫 나무의 4단계 온보딩으로 이어진다.
3. 첫 순간부터 URL·출처·제목·날짜·영상 시점·감정·메모를 저장할 수 있어야 한다.
4. 두 번째 순간부터 `parentId`와 별도로 관계 이유를 저장한다.
5. 일상 편집 화면은 `growing-tree-v6`의 3열 작업공간을 기준으로 한다.
6. 고급 연결 편집은 `node-graph-prototype`을 별도 모드로 둔다.
7. 타임라인·다이어리·스토리·앨범·연결 지도는 동일한 Memory 데이터의 보기 모드다.
8. 사람별 앨범은 여러 트리를 묶는 상위 정리 계층으로 사용한다.
9. 공개 탐색은 `community-discovery-v2`의 검색·필터·미리보기와 TSX의 실제 API를 결합한다.
10. 300개 등 성장 마일스톤 시각화는 상시 기본 UI가 아니라 축하·회고 모드로 사용한다.

## 3. 파일별 실제 기능 조사

### 3.1 랜딩·첫 생성 계열

#### A. `complete-manga-refinement`

**화면 흐름**

1. 홈 랜딩
2. `첫 순간 심기` 클릭
3. 트리 이름 모달
4. 이름 제출
5. 첫 발견 입력 화면
6. `이 순간 심기` 후 성공 토스트

**입력값**

- 러브트리 이름
- 콘텐츠 URL
- 첫 발견 메모
- 발견 날짜

**동작**

- YouTube URL을 파싱해 미리보기 이미지와 제목 영역을 바꾼다.
- 이름 모달 제출 시 랜딩을 감추고 발견 화면을 표시한다.
- 최종 제출은 성공 토스트까지만 만들며 영속 저장은 없다.

**장점**

- LoveTree의 감성적 정의가 가장 명확하다.
- ‘트리 이름’과 ‘첫 순간’을 구분한다.
- 입력 옆에 결과가 어떻게 보일지 미리 보여준다.

**한계**

- 저장·인증·서버 연결이 없다.
- URL의 실제 메타데이터 수집은 제한적이다.
- 첫 발견 이후 감정·관계 단계가 이 파일 안에는 없다.

#### B. `step2-emotion-refined`

**입력값**

- 영상 내 시점 `MM:SS`
- 감정 프리셋: 설렘, 웃음, 위로, 놀람, 존경, 애틋함
- 직접 감정
- 메모 최대 140자
- 날짜
- 메모 공개 여부

**버튼과 동작**

- 영상 재생
- 현재 시점 동기화
- 5초 전·후 조절
- `첫 마음 카드 피우기`
- 성공 후 `다시 다듬기`, `첫 여정 보기`

**저장 결과**

`localStorage`의 `lovetree-step2-record`에 URL, 제목, 시점, 감정, 메모, 날짜, 공개 여부를 저장한다.

**장점**

- 영상의 정확한 순간과 감정·문장을 결합한다.
- 감정 프리셋과 자유 입력을 동시에 제공한다.
- 저장 후 성공 상태와 수정 복귀가 분명하다.

**한계**

- 서버 저장이 아니다.
- 단일 대표 감정과 태그 배열의 관계가 명확하지 않다.
- 공개 여부가 메모 단위인지 순간 전체 공개인지 데이터 모델이 불분명하다.

#### C. `step3-connect-next-video`

**입력값**

- 다음 영상 URL
- 다음 순간 제목
- 영상 내 시점
- 메모
- 관계 이유

**관계 프리셋**

- 댓글을 따라갔어요
- 팬의 추천
- 다른 모습이 궁금했어요
- 같은 무대·노래
- 직접 다시 검색

**저장 결과**

`localStorage`의 `lovetree-step3-connection`에 첫 순간, 다음 순간, 생성 시각을 저장한다.

**핵심 동작**

- 첫 카드와 다음 카드가 실시간으로 한 보드에 보인다.
- 관계 선택에 따라 두 카드 사이 설명이 바뀐다.
- 저장 성공 후 다음 영상을 새 출발점으로 승격해 연속 추가할 수 있다.

**장점**

- LoveTree가 단순 북마크가 아니라 ‘왜 다음으로 갔는지’를 기록하는 제품임을 보여준다.
- 부모 순간과 새 순간을 동시에 보며 연결할 수 있다.

**한계**

- 후속 이동 파일명이 현재 파일 세트와 맞지 않는다.
- 서버 저장·트리 ID 연결이 없다.

### 3.2 일상 성장·편집 계열

#### D. `growing-tree-v5`

**화면 구조**

- 왼쪽: 문구·마음 다이어리
- 가운데: 성장 트리 캔버스
- 오른쪽: 새 가지 입력 폼

**입력값**

- 영상 URL
- 영상 시점
- 날짜
- 관계 프리셋
- 메모

**작업 기능**

- 순간 카드 추가·삭제
- 다이어리 항목과 트리 카드 동기화
- 카드 드래그
- 캔버스 팬
- 확대·축소·전체 맞춤
- 전체화면
- 샘플 초기화

**저장**

- `lovetree-v5` 로컬 저장
- 이전 `lovetree-v4` 데이터 마이그레이션
- 카드 위치까지 저장

**장점**

- 실제 장기 사용 작업공간의 형태가 가장 구체적이다.
- 트리와 일기를 같은 데이터로 보여준다.
- 노드 위치를 사용자가 조정할 수 있다.

**한계**

- 제목보다 메모가 카드 핵심 문구로 쓰인다.
- 모든 사용자가 항상 드래그 가능한 상태라 실수 위험이 있다.
- 로컬 저장이라 협업·다중 기기 사용이 불가능하다.

#### E. `growing-tree-v6`

v5를 기반으로 다음을 추가한다.

- 전체화면 상태에서 입력 가능한 추가창
- 추가창 열기·닫기
- 일반 폼과 전체화면 폼의 동일 저장 로직
- ESC로 드로어·전체화면 종료
- 순간이 많아졌을 때 다이어리 스크롤 강화

**판단**

일상적인 공식 트리 편집 화면은 v6를 중심으로 설계해야 한다. 다만 자유 드래그는 기본 모드가 아니라 `배치 편집`을 켰을 때만 활성화해야 한다.

### 3.3 고급 그래프 계열

#### F. `node-graph-prototype`

**입력값**

- 제목
- URL
- 시작 시점
- 종료 시점
- 감정

**주요 기능**

- 여러 시간 형식 해석: 초, `MM:SS`, `HH:MM:SS`, URL의 `t`/`start`
- 시작 시점과 종료 시점 검증
- YouTube 썸네일과 시간 링크 생성
- 노드 네 방향 핸들로 연결선 생성
- 노드 드래그·삭제·다음 노드 추가
- 방사형·트리·원형·그리드 배치
- 캔버스 팬·줌·미니맵
- 노드 모달, 좋아요, 감정 온도

**판단**

일상 입력 화면으로는 복잡하지만, 이미 많은 순간을 가진 사용자에게 필요한 고급 편집기다. 공식 제품에서는 `연결 지도 > 편집 모드`로 격리한다.

#### G. `obsidian-graph1`

- 영상 노드와 감정 노드를 함께 둔다.
- 제목·계정 검색, 감정 필터가 있다.
- 연결 모드에서 시작 노드와 대상 노드를 순서대로 선택한다.
- 자동 레이아웃과 선택 검사 패널을 제공한다.

**판단**

감정 노드를 독립 엔터티로 둘지 여부는 공식 모델에서 채택하지 않는다. 감정은 기본적으로 Memory의 속성으로 유지하고, 연결 지도에서만 집계 노드로 시각화한다.

#### H. `love-nebula`

- 감정별 클러스터
- 100/300/1000 밀도
- 성운·꽃망울·나선 패턴
- 팬·줌·선택·드래그

**판단**

CRUD에는 적합하지 않지만 100개 이상 순간을 빠르게 조망하는 ‘대규모 지도’로 가치가 있다.

### 3.4 보기·정리 계열

#### I. `juyeon-timeline`

## 4. 현재 TSX 사이트 조사

### 4.1 기술 기반

현재 저장소는 Next/React/TypeScript 기반이며 Firebase 인증, Neon/Drizzle 데이터 계층, API 라우트와 실제 CRUD를 갖고 있다.

현재 `main`에는 사실상 두 개의 겹치는 사용자 여정이 있다.

1. 루트 `/` 계열
2. `/v2` 계열

둘은 같은 브랜드와 API를 사용하지만 입력 순서와 화면 구성이 다르다. 통합 구현 전에 반드시 하나의 공식 경로로 합쳐야 한다.

### 4.2 루트 `/` 여정

1. 랜딩
2. `첫 순간 심기`
3. 이름 모달
4. 로그인
5. 빈 트리 POST
6. 발견 화면
7. 출처 종류·메모·날짜 입력
8. 첫 Memory POST
9. `/trees/:id` 이동

**장점**

- HTML의 랜딩 톤을 가장 가깝게 유지한다.
- 공개 둘러보기와 실제 API가 연결된다.
- 빈 상태·오류·로딩 처리가 있다.

**핵심 손실**

- 첫 순간 URL 입력이 없다.
- 제목이 없다.
- 영상 내 시점이 없다.
- 감정 프리셋·직접 감정이 없다.
- 관계 이유가 없다.
- 첫 순간을 저장하기 전에 빈 트리를 먼저 만든다.

### 4.3 `/v2` 여정

`/v2`는 다음 경로를 가진다.

- `/v2`
- `/v2/my-trees`
- `/v2/trees/:id`
- `/v2/community`

트리 상세는 다음 보기 모드를 가진다.

- 성장 트리
- 마음 다이어리
- 스토리
- 앨범 보드

Moment 편집기는 다음 필드를 지원한다.

- sourceType
- title
- source
- sourceUrl
- 날짜
- memo
- emotionTags
- parentId

**장점**

- HTML보다 데이터 필드가 서버 모델에 더 잘 연결돼 있다.
- 생성·수정·삭제와 공개·비공개 전환이 된다.
- 동일 Memory를 여러 보기에서 소비한다.

**핵심 문제**

- 새 트리를 `public`으로 하드코딩한다.
- 첫 생성 모달에서는 트리 이름과 설명만 받는다.
- 영상 시작·종료 시점이 없다.
- `timestamp`를 기록 날짜로 사용해 영상 시점과 의미가 충돌한다.
- `parentId`는 있으나 연결 이유가 없다.
- 성장 트리는 최대 8개만 고정 위치에 보여준다.
- 수백 개 데이터에 대응하는 그래프·타임라인 구조가 아니다.
- 루트 여정과 중복돼 유지보수 충돌이 발생한다.

### 4.4 저장소 문서 드리프트

README는 백엔드·인증·배포가 범위 밖이라고 적고 일부 스크립트가 없다고 설명하지만, 현재 코드와 `package.json`은 이미 백엔드·인증·typecheck를 포함한다. 통합 작업에서 README와 운영 문서를 현재 상태로 갱신해야 한다.

### 4.5 Preview 검증 한계

제공된 Preview 주소는 이번 분석 환경에서 직접 로드되지 않아 실제 브라우저 런타임을 독립 확인하지 못했다. 따라서 Preview 화면에 관한 최종 판단은 하지 않았고, GitHub `main`의 라우팅·컴포넌트·상태 전이를 기준으로 분석했다. 구현 단계에서는 Preview exact SHA를 배포한 뒤 별도 브라우저 acceptance가 필요하다.

## 8. 공식 LoveTree 사용자 여정

### 단계 0. 공개 랜딩

사용자는 제품을 먼저 이해한다.

- 주 CTA: `첫 순간 심기`
- 보조 CTA: `러브트리 둘러보기`
- 소개: 발견 → 마음 → 연결 → 성장
- 샘플 트리는 실제 데이터가 아니라 명확히 ‘예시’로 표시

### 단계 1. 트리 씨앗 정하기

필수

- 러브트리 이름

선택

- 짧은 설명
- 대상 유형: 사람, 작품, 여행, 공부, 관계, 기타
- 대상 이름

저장

- 로그인이 없으면 입력 상태를 유지한 채 인증
- 서버에 `draft/private` 트리 생성

### 단계 2. 첫 순간 발견

필수 또는 강력 권장

- 출처 종류
- URL 또는 파일
- 순간 제목
- 기록 날짜

영상일 때

- 미리보기
- 시작 시점
- 고급 옵션으로 종료 시점
- `현재 시점 가져오기`, `-5초`, `+5초`

### 단계 3. 마음 남기기

- 대표 감정 프리셋 하나
- 추가 감정 태그
- 메모
- 메모 공개 범위
- 카드 미리보기

저장 후 첫 Memory 생성

### 단계 4. 다음 순간 연결

사용자에게 두 선택을 제공한다.

- `다음 순간 이어보기`
- `일단 첫 나무 펼쳐보기`

이어보기를 선택한 경우

- 부모 순간 확인
- 새 URL·제목·시점·날짜
- 관계 이유
- 메모·감정
- 두 카드와 연결선 실시간 미리보기

### 단계 5. 첫 나무 공개

- 개념적 트리 루트
- 첫 순간과 두 번째 순간을 한 번씩만 표시
- 저장 성공 애니메이션
- `새 가지 추가`, `다이어리 보기`, `공개 설정` 제공

### 단계 6. 일상 작업공간

기본 3열

- 왼쪽: 다이어리·날짜 목록·필터
- 가운데: 성장 트리
- 오른쪽: 새 순간/선택 순간 편집기

도구

- 확대·축소·전체 맞춤
- 전체화면
- 새 순간 드로어
- 배치 편집
- 실행 취소
- 삭제 확인

### 단계 7. 동일 데이터의 보기 모드

- 성장 트리: 기본
- 연혁: 날짜 중심
- 다이어리: 문장 중심
- 스토리: 선형 서사
- 앨범: 미디어 중심
- 연결 지도: 관계 중심 고급 보기
- 성운: 대량 데이터 요약

### 단계 8. 내 정원

- 전체 트리 카드
- 사람/주제 앨범
- 검색·필터·정렬
- 최근 편집, 순간 수, 공개 상태
- 그리드 보기 기본
- 선반 보기 선택

### 단계 9. 공개 정원

- 검색
- 감정·주제 필터
- 최신·인기·조회·순간 수 정렬
- 카드 선택 시 빠른 미리보기
- 전체 트리 오버레이
- 좋아요, 저장, 댓글
- 작성자 소유 트리와 공개 트리의 권한 분리

### 단계 10. 성장 마일스톤

예시

- 10: 첫 가지 묶음
- 50: 작은 수관
- 100: 기억 성운
- 300: 완성 축하

사용자는 트리·하트·꽃·은하·무지개 수관 중 테마를 고를 수 있다.

### 중요 마이그레이션

현재 `timestamp`는 기록 날짜로 쓰이고 HTML에서는 영상 시점으로 쓰인다. 그대로 확장하면 데이터 오류가 생긴다. 반드시 다음으로 분리한다.

- `recordDate`
- `startSeconds`
- `endSeconds`

당신은 `skerishKang/lovetree-limone` 저장소의 Web CTO 겸 구현 오케스트레이터다.

이번 작업의 목적은 현재 `/` 및 `/v2`에 중복 구현된 TSX 사용자 여정을 정리하고,

# 절대 규칙

1. 시작 시 최신 `origin/main` exact SHA, working tree, open PR, CI를 직접 확인한다.
2. 사용자 승인 없이 Production 배포, main 직접 수정, 기존 데이터 삭제를 하지 않는다.
3. `/`와 `/v2`를 병렬 제품으로 남기지 않는다. 하나의 canonical 경로로 통합한다.
4. 현재 Firebase 인증, Neon/Drizzle, API CRUD 기반을 보존한다.
5. V2의 `visibility: "public"` 하드코딩을 제거하고 기본값을 `private`로 한다.
6. `timestamp`를 영상 시점과 날짜에 중복 사용하지 않는다.
7. localStorage는 초안 복구·구버전 가져오기에만 사용하고 서버 데이터를 원본으로 한다.
8. 하드코딩 샘플 데이터가 실제 사용자 데이터처럼 보이지 않게 한다.
9. 구현자 자체 브라우저 검증을 독립 acceptance라고 선언하지 않는다.
10. 코드 수정 전에 통합 설계 문서와 데이터 마이그레이션 계획을 Draft PR에 먼저 제시한다.

# 필수 검증

- 인증을 거쳐도 작성 중인 입력이 유지된다.
- 첫 순간 URL, 제목, 날짜, 영상 시점, 감정, 메모가 서버에서 다시 읽힌다.
- 두 번째 순간은 parentId와 relationType을 함께 저장한다.
- 첫 순간이 개념 루트와 중복 카드로 두 번 표시되지 않는다.
- private 트리가 커뮤니티에 노출되지 않는다.
- owner와 public viewer의 편집 권한이 분리된다.
- 성장 트리가 8개를 넘어도 데이터가 사라지지 않는다.
- 모든 보기 모드가 동일한 Memory 수와 내용을 표시한다.
- 노드 위치 저장과 자동 배치 복귀가 작동한다.

## 13. 최종 제품 원칙

LoveTree의 핵심은 ‘영상 카드 수집’도 ‘예쁜 트리 애니메이션’도 아니다.

공식 제품의 중심은 다음 문장으로 정리된다.

> 한 순간을 발견하고, 그때의 마음을 남기고, 왜 다음 순간으로 이어졌는지를 연결해 시간이 쌓인 나만의 사랑 연혁을 만드는 서비스.

따라서 모든 기능은 아래 우선순위를 따른다.

1. 발견한 원본과 정확한 시점
2. 그때의 감정과 문장
3. 이전·다음 순간 사이의 관계
4. 장기적으로 다시 찾을 수 있는 구조
5. 성장의 감성적 보상

시각화는 이 데이터를 돋보이게 해야 하며 데이터를 대신해서는 안 된다.
