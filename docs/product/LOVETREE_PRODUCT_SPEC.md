## 0. 한 문장 정의

> **LoveTree는 누군가 또는 무엇인가를 처음 발견한 순간부터 완전히 빠져들기까지의 콘텐츠·감정·행동 경로를 아주 쉽게 저장하고, 그 경로를 다시 걸어 당시의 감정을 되살리며, 다른 사람도 같은 길을 따라 새로운 팬이나 사용자로 전환되게 만드는 몰입 경로 플랫폼이다.**

LoveTree의 기본 단위는 단순한 영상이나 게시물이 아니다. **마음이 움직인 순간**이다.  
LoveTree의 연결선은 단순한 순서나 폴더 구조가 아니다. **다음 탐색을 일으킨 감정의 인과관계**다.  
LoveTree의 완성은 단순히 영상 수가 많아지는 것이 아니다. 사용자가 “이때 나는 완전히 빠졌다”고 인식하는 **감정 전환점**이다.  
LoveTree의 공유는 완성된 결과물을 전시하는 데서 끝나지 않는다. 다른 사람이 그 경로를 직접 따라가며 같은 대상을 좋아하게 만드는 **팬 전환 경로**다.

# 1. LoveTree가 포착하려는 실제 인간 경험

사람이 누군가에게 빠지는 과정은 정보 검색 목록처럼 깔끔하지 않다.

처음에는 우연히 한 영상을 본다. 이름도 잘 모르지만 특정 표정이나 말투, 행동이 이상하게 신경 쓰인다. “어떻게 이런 표정을 짓지?”, “왜 저런 행동을 하지?”, “이 사람은 뭐지?”라는 질문이 생긴다. 호감만 생기는 것도 아니다. 낯설거나 거부감이 들기도 하고, 다시 보면 갑자기 좋아지기도 한다.

그다음에는 관련 영상을 찾기 시작한다.

- YouTube 쇼츠와 무대 영상
- 예능·인터뷰·라이브 영상
- Instagram
- X·Twitter
- TikTok
- Facebook
- 블로그와 카페
- 네이버 검색
- 위키·나무위키
- 더쿠·여시 등 커뮤니티
- 팬 편집 영상
- 국내외 리액션 영상
- Patreon 등 해외 팬 콘텐츠

검색은 한 플랫폼에서 끝나지 않는다. 사용자는 하루 종일 콘텐츠를 넘나들며 대상의 다른 면을 확인한다. 실력을 확인하고, 성격을 궁금해하고, 팬들의 반응을 보며 자신의 감정을 검증한다. 어느 순간에는 눈을 감아도 계속 생각나고, 자신도 모르게 음반·굿즈·팬클럽·위버스·버블 같은 다음 행동으로 이동한다.

그러나 너무 많은 콘텐츠를 본 뒤에는 처음의 설렘이 흐려진다.

- 내가 처음 어떤 부분에 반했는지 기억나지 않는다.
- 너무 많은 시간을 썼다는 생각에 현타가 온다.
- 잠시 쉬고 싶어진다.
- 그래도 처음의 마음은 잃고 싶지 않다.
- 얼마나 많이 탐구했는지 한눈에 보고 싶다.
- 내가 찾은 귀한 장면과 경로를 소장하고 싶다.
- 다른 팬에게 “내 트리를 한번 따라와 봐”라고 자랑하고 싶다.

LoveTree는 바로 이때 필요하다.

LoveTree는 본 영상의 목록을 다시 보여주는 서비스가 아니다. **내가 사랑에 빠진 과정과 그때의 감정을 복원하는 장치**다.

# 2. 핵심 제품 철학: 감정의 인과관계

## 2.1 노드는 콘텐츠가 아니라 순간이다

같은 영상이라도 사람마다 기억하는 순간이 다르다.

- 01:30의 표정
- 무대가 끝난 뒤 웃는 장면
- 인터뷰에서 특정 문장을 말한 순간
- 팬 댓글을 보고 다시 재생한 구간
- 처음에는 이상했지만 다시 보니 매력적으로 느낀 장면

따라서 LoveTree의 노드는 다음을 묶은 **Moment**다.

- 원본 콘텐츠
- 기억할 정확한 지점 또는 구간
- 당시 날짜
- 당시 감정
- 내가 남긴 말
- 이 순간을 찾게 된 이유
- 다음 행동에 미친 영향

## 2.2 가지는 감정의 인과관계다

일반적인 재생목록의 선은 “다음 영상”을 의미한다. LoveTree의 가지는 다음 질문에 답해야 한다.

> **왜 이 순간 다음에 저 순간으로 갔는가?**

예시:

```text
처음 본 쇼츠
→ 표정이 이상하게 신경 쓰여서 무대를 검색함
→ 생각보다 실력이 좋아 놀라 인터뷰를 찾아봄
→ 무대 밖 말투가 궁금해 예능 영상을 봄
→ 인간적인 모습에 호감이 커져 팬 리액션을 찾아봄
→ 다른 팬들의 감정을 보며 내가 좋아한다는 사실을 인정함
→ 완전히 입덕함
```

가능한 관계 이유:

- 우연히 처음 발견했다
- 표정이 계속 생각났다
- 댓글을 따라갔다
- 팬이 추천했다
- 다른 모습이 궁금했다
- 실력을 확인하고 싶었다
- 성격이 궁금했다
- 처음에는 낯설어서 다시 확인했다
- 거부감이 있었지만 자꾸 신경 쓰였다
- 직접 다시 검색했다
- 같은 무대의 다른 직캠을 찾았다
- 리액션을 보고 내 감정을 확인했다
- 위키에서 본 사실을 확인하고 싶었다
- 한동안 쉬었다가 다시 돌아왔다
- 이 영상에서 완전히 빠졌다고 느꼈다

따라서 데이터에서 `parentId`만 저장해서는 부족하다. 최소한 다음이 필요하다.

- `parentMomentId`
- `relationType`
- `relationLabel`
- `relationMemo`
- `relationEmotionBefore`
- `relationEmotionAfter`

## 2.3 감정은 정적인 태그가 아니라 변화다

감정은 한 영상에 하나씩 붙는 장식이 아니다. 감정은 시간과 경로에 따라 움직인다.

```text
낯섦
→ 궁금함
→ 약한 거부감
→ 재확인
→ 놀람
→ 호감
→ 설렘
→ 몰입
→ 집착
→ 완전한 입덕
→ 현타
→ 휴식
→ 재회
→ 안정된 애정
```

한 순간에는 대표 감정 하나와 여러 보조 감정을 둘 수 있다. 그러나 연결선에는 **감정의 변화**를 표현해야 한다.

예시:

```text
이전 감정: 낯섦
새 감정: 궁금함
변화 이유: 웃는 표정이 예상과 달라 다시 찾아봤다.
```

## 2.4 트리는 저장되는 것이 아니라 재생되어야 한다

LoveTree의 결정적 차별점은 트리가 살아 움직이는 데 있다.

사용자가 `처음부터 다시 걷기`를 누르면:

1. 첫 순간이 천천히 빛난다.
2. 정확한 영상 구간이 열린다.
3. 그때의 한 줄 감정이 나타난다.
4. 다음 가지가 자라난다.
5. 가지 위에 “왜 다음으로 갔는지”가 표시된다.
6. 다음 영상과 당시 감정이 살아난다.
7. 사용자가 완전히 빠진 순간에 꽃이나 열매가 피어난다.
8. 현타·휴식 구간에서는 움직임이 느려지고 나무 아래 쉼 화면으로 전환된다.
9. 다시 돌아온 순간에는 새 잎이 열리며 재회 감정을 보여준다.

트리는 데이터 시각화가 아니라 **감정 재생 장치**여야 한다.

# 3. LoveTree의 제품 헌법

다음 원칙은 향후 UI·UX·데이터 모델·결제·커뮤니티·앱·확장 프로그램·기획사 기능을 판단하는 최상위 기준이다.

1. **LoveTree의 기본 단위는 영상이 아니라 발견 순간이다.**
2. **모든 순간은 당시의 감정과 함께 저장되어야 한다.**
3. **모든 연결은 다음 탐색을 일으킨 이유를 가질 수 있어야 한다.**
4. **트리는 단순 목록이 아니라 감정의 인과관계를 보여줘야 한다.**
5. **트리는 언제든 처음부터 다시 재생할 수 있어야 한다.**
6. **처음 저장은 어떤 플랫폼에서도 1~3번의 동작으로 끝나야 한다.**
7. **자동으로 알 수 있는 정보는 사용자가 입력하게 하지 않는다.**
8. **사용자는 감정 하나 또는 한 줄만 남겨도 저장을 끝낼 수 있어야 한다.**
9. **현재의 성장 트리·마음 다이어리·스토리·앨범 보드는 유지한다.**
10. **같은 데이터를 여러 방식으로 읽되 중복 저장하지 않는다.**
11. **공개와 비공개는 사용자가 순간·메모·트리별로 통제한다.**
12. **다른 사람의 트리를 감상하는 행위가 새 팬과 새 트리 생성으로 이어져야 한다.**
13. **추천자의 보상은 단순 업로드 수보다 실제 채택·완주·팬 전환을 기준으로 한다.**
14. **기획사 공식 경로와 팬의 실제 경로를 명확히 구분한다.**
15. **현타와 휴식은 이탈이 아니라 제품 여정의 일부로 존중한다.**
16. **300번째 순간은 결제 차단이 아니라 축하와 완성의 순간이어야 한다.**
17. **사용자의 원본 콘텐츠 소유권을 침해하지 않고 링크·구간·감정·주석 중심으로 작동한다.**
18. **팬덤에서 먼저 강한 제품을 만든 뒤 공부·여행·투자 등으로 확장한다.**

# 4. 전체 감정 여정

## 4.1 단계 A: 발견

사용자는 우연히 한 콘텐츠를 만난다.

- 쇼츠가 자동 재생된다.
- 친구가 링크를 보낸다.
- 커뮤니티 게시물을 본다.
- 팬의 트리를 따라가다가 특정 장면에서 멈춘다.
- 기획사의 공식 입덕 경로에서 첫 콘텐츠를 본다.

이때 가장 중요한 것은 “트리를 제대로 만들기”가 아니라 **마음이 움직인 순간을 놓치지 않는 것**이다.

최소 행동:

```text
공유 → LoveTree → 감정 하나 → 저장
```

또는:

```text
URL 붙여넣기 → 저장
```

## 4.2 단계 B: 궁금함과 탐색

사용자는 대상을 더 알고 싶어진다.

- 이름을 검색한다.
- 다른 무대를 찾는다.
- 예능·인터뷰를 본다.
- Instagram과 X로 이동한다.
- 블로그·카페·커뮤니티·위키를 찾아본다.
- 팬 리액션과 해외 리액션을 본다.

LoveTree는 사용자가 본 모든 것을 무조건 자동 수집하는 감시 도구가 아니라, **사용자가 마음이 움직였다고 선택한 순간**을 중심으로 기록한다. 사용자가 동의한 경우 탐색 시간·플랫폼 이동·저장량을 통계로 측정할 수 있다.

## 4.3 단계 C: 감정의 진동

좋아짐은 직선이 아니다.

- 신기함
- 낯섦
- 거부감
- 계속 생각남
- 다시 봄
- 호감
- 설렘
- 부정
- 인정

이 단계에서 LoveTree는 긍정적인 감정만 강요하면 안 된다. “잘 모르겠음”, “낯섦”, “약간 부담”, “자꾸 신경 쓰임”, “다시 확인하고 싶음” 같은 감정도 저장할 수 있어야 한다.

## 4.4 단계 D: 완전한 입덕

어느 순간 사용자는 “이제 나는 이 사람을 좋아한다”고 인정한다.

이 시점은 시스템이 영상 수만으로 정하지 않는다.

- 사용자가 직접 `완전히 빠진 순간`을 선언
- 탐색 시간과 저장 수를 참고한 추천
- 특정 행동 전환 발생
- 감정 강도의 변화

예시 행동 전환:

- 음반 구매
- 굿즈 구매
- 팬클럽 가입
- Weverse·Bubble 가입
- 공연·팬미팅 예매
- 공식 계정 팔로우
- YouTube 채널 구독
- 유료 팬 콘텐츠 가입

입덕 완료는 트리의 끝이 아니라 **새 성장 단계의 시작**이다.

## 4.5 단계 E: 몰입과 축적

사용자는 수십·수백 개의 순간을 저장한다.

- 같은 사람의 서로 다른 매력
- 무대·예능·인터뷰·팬캠·리액션
- 플랫폼별 콘텐츠
- 감정별 클러스터
- 시기별 변화
- 관련 인물과 관계

이 단계에서는 한 화면에 모든 것을 우겨 넣지 않는다. 같은 데이터를 여러 보기로 제공한다.

## 4.6 단계 F: 현타와 휴식

많이 본 뒤에는 피로와 현타가 올 수 있다.

LoveTree는 이를 실패나 이탈로 취급하지 않는다. 사용자가 잠시 멈출 수 있는 **나무 아래 쉼**을 제공한다.

가능한 기능:

- `나무 아래 잠시 쉬기`
- `알림 잠시 멈추기`
- `새 추천 숨기기`
- `처음의 설렘만 다시 보기`
- `내 첫 5개의 순간`
- `완전히 빠지기 전의 기록`
- `내 마음이 바뀐 순간`
- `한 달 전 오늘의 기억`
- `조용한 감상 모드`
- `휴식 메모 남기기`

휴식 중에는 성장 압박·연속 기록·랭킹 경쟁을 줄인다. 사용자가 돌아오면 `다시 나무로 돌아온 날`이라는 재회 순간을 선택적으로 기록한다.

## 4.7 단계 G: 회상과 재몰입

시간이 지난 뒤 사용자는 다음 질문을 한다.

- 내가 처음 무엇에 반했지?
- 어느 영상에서 마음이 바뀌었지?
- 얼마나 많은 플랫폼을 탐구했지?
- 어떤 감정이 가장 많았지?
- 무엇을 본 뒤 팬클럽에 가입했지?

LoveTree는 경로를 재생해 처음의 감정을 되살린다. 이때 HTML의 성장 애니메이션, 마음꽃, 성운, 오로라, 무지개 수관, 300개 완성 장면이 회고 인터페이스로 작동한다.

## 4.8 단계 H: 자랑과 전파

사용자는 자신의 트리를 공개한다.

> “내가 이 사람에게 빠진 경로를 처음부터 따라와 봐.”

다른 사람은 트리를 감상하고:

- 영상을 재생한다.
- 당시 감정을 읽는다.
- 가지를 선택한다.
- 댓글을 남긴다.
- 하트를 보낸다.
- 해당 순간을 자신의 트리에 저장한다.
- 같은 대상의 새 LoveTree를 시작한다.

이 순간 개인 아카이브가 **팬 전환 플랫폼**으로 바뀐다.

# 5. A의 LoveTree에서 B의 LoveTree가 태어나는 구조

## 5.1 기본 파생 흐름

```text
A가 자신의 LoveTree를 공개
→ B가 A의 첫 순간부터 감상
→ B가 특정 영상과 감정에 공감
→ B가 하트·댓글·저장
→ B가 “내 첫 순간으로 심기” 선택
→ A의 트리를 출처로 한 B의 LoveTree 생성
→ B가 이후 자신의 경로를 추가
→ 새로운 팬과 새로운 트리 탄생
```

## 5.2 원본과 파생의 관계

B의 트리는 A의 트리를 복제하는 것이 아니다.

- B가 채택한 출발 순간
- A의 추천으로 들어온 경로
- B만의 감정
- B가 새로 찾은 콘텐츠
- B의 독자적인 가지

를 갖는다.

데이터에는 다음 출처를 남긴다.

- `derivedFromTreeId`
- `derivedFromMomentId`
- `referrerUserId`
- `adoptionRouteId`
- `adoptedAt`

## 5.3 A에게 돌아가는 가치

A는 다음을 확인할 수 있다.

- 내 트리를 본 사람 수
- 첫 순간부터 끝까지 따라온 사람 수
- 각 가지에서 이탈한 사람 수
- 가장 많이 재생된 순간
- 가장 많이 저장된 순간
- 내 트리에서 파생된 새 트리 수
- 실제 입덕 선언 수
- 팬클럽·공식 채널·굿즈 등 다음 행동으로 간 수
- 국가·언어별 파생 흐름

A의 성과는 단순 조회 수가 아니다. **다른 사람의 마음을 움직여 새 팬 경로를 만든 정도**다.

## 5.4 B에게 필요한 자유

B는 A의 경로를 그대로 따라야 할 의무가 없다.

- 다른 가지 선택
- 중간 건너뛰기
- 새로운 영상 삽입
- 감정 다르게 기록
- A의 추천을 거절
- 공식 경로와 팬 경로 혼합

이 자유가 있어야 LoveTree는 선전물이 아니라 개인 감정 플랫폼이 된다.

# 6. 실제 탐색 경로와 전파용 입덕 코스의 분리

사용자의 실제 탐색은 복잡하고 비효율적일 수 있다.

```text
쇼츠 → 직캠 17개 → 댓글 → X → 인터뷰 → 나무위키 → 예능 → 해외 리액션 → 다시 첫 무대
```

하지만 다른 사람에게 보여줄 때는 가장 좋은 순간만 골라 짧은 경로를 만들 수 있다.

따라서 LoveTree에는 두 종류의 구조가 필요하다.

## 6.1 나의 실제 경로

- 실제 발견 순서
- 당시 감정 변화
- 우회와 반복 포함
- 현타와 휴식 포함
- 개인 기록 중심

## 6.2 전파용 추천 경로

- 친구에게 보여줄 입덕 코스
- 5분 입문 코스
- 15분 핵심 코스
- 30분 입덕 코스
- 완전 정복 코스
- 무대 중심 코스
- 예능 중심 코스
- 성격 중심 코스
- 감정별 코스
- 시기별 코스
- 초보자용·기존 팬용 코스

사용자는 실제 트리에서 일부 순간을 골라 여러 개의 `Route`를 만들 수 있다.

# 7. 기획사·아티스트 공식 입덕 경로

## 7.1 중소기획사에 필요한 이유

중소기획사나 신인 아티스트는 좋은 콘텐츠가 있어도 새로운 사람이 어떤 순서로 봐야 팬이 되는지 정리하지 못하는 경우가 많다.

LoveTree는 단순 홍보 페이지가 아니라 **콘텐츠를 팬 전환 순서로 설계하는 도구**가 될 수 있다.

공식 예시:

```text
15초 첫 발견 영상
→ 대표 무대
→ 실력 확인 영상
→ 성격을 알 수 있는 자체 콘텐츠
→ 멤버 관계 영상
→ 진솔한 인터뷰
→ 팬 반응과 리액션
→ 최신 활동
→ 공식 채널 구독
→ 음반·공연·팬클럽
```

## 7.2 세 가지 트리 유형

### 공식 LoveTree

기획사·아티스트가 만든 공식 입문 경로다.

- 공식 인증 표시
- 정확한 출처
- 다국어
- 활동별 경로
- 신규 팬용 코스
- 공식 상품과 일정 연결

### 팬 LoveTree

개인 팬의 실제 감정 경로다.

- 주관적 감정
- 우회·거부감·현타 포함 가능
- 팬만이 아는 순간
- 독창적인 안목

### 공식×팬 협업 LoveTree

기획사와 대표 팬 큐레이터가 함께 만든다.

- 공식 정보의 정확성
- 팬 경로의 진정성
- 팬 투표로 선정한 순간
- 시즌별 공동 편집

## 7.3 기획사 이벤트

가능한 이벤트:

- 100·300·500번째 순간 달성 리워드
- 공식 LoveTree 완주자 배지
- 가장 많이 파생된 팬 트리 선정
- 팬 큐레이터 공동 편집권
- 아티스트 음성 축하 메시지
- 디지털 인증서
- 미공개 이미지·영상 공개
- 음반·굿즈·공연 티켓 선물
- 300개 완성 팬에게 공식 굿즈 제공
- 국가별 대표 LoveTree Maker 선정

기획사의 리워드는 결제 유도보다 **팬의 탐구와 큐레이션에 대한 인정**으로 설계해야 한다.

## 7.4 기획사 분석 지표

- 어느 영상에서 팬 전환이 많이 발생했는지
- 어느 순서에서 완주율이 높은지
- 어떤 국가에서 어떤 매력이 반응하는지
- 공식 경로와 팬 경로의 차이
- 굿즈·팬클럽 행동 전환 직전의 콘텐츠
- 팬이 자발적으로 만든 핵심 순간
- 새 아티스트를 발굴한 초기 팬

# 9. 쉽고 빠른 입력: LoveTree의 최우선 경쟁력

사용자의 핵심 모토는 명확하다.

> **Instagram, X, Facebook, Patreon, Postype처럼 무조건 쉽게 올리고, 쉽게 공유하고, 쉽게 감상되어야 한다.**

## 9.1 최초 저장은 최소 입력

필수 입력을 늘리지 않는다.

```text
콘텐츠 공유 또는 URL 입력
→ 저장할 LoveTree 선택
→ 감정 하나 또는 한 줄
→ 저장 완료
```

트리 이름이나 세부 분류가 아직 없으면 임시 트리를 자동 생성할 수 있다.

## 9.2 자동 추출

URL에서 가능한 경우 자동으로 가져온다.

- 플랫폼
- 원본 URL
- 제목
- 썸네일
- 작성자·채널
- 게시 날짜
- 영상 길이
- 공유된 시작 시점
- 현재 재생 시점
- 대상 인물 후보

## 9.3 선택 입력

- 기억할 시작 시점
- 종료 시점
- 대표 감정
- 추가 감정
- 한 줄 메모
- 이전 순간
- 이어진 이유
- 관련 사람
- 공개 범위

## 9.4 나중에 정리

사용자가 몰입 중일 때 긴 폼으로 방해하지 않는다. 우선 저장한 뒤 `나중에 다듬기`에서 다음을 보완한다.

- 태그
- 관계 이유
- 정확한 시간
- 인물
- 코스 편입
- 공개 메모
- 트리 배치

## 9.5 영상 편집의 제품 해석

초기 구상의 `영상 편집 가능`은 원본을 무단 복제·재업로드하는 방식보다 다음으로 구현하는 것이 적절하다.

- 시작·종료 구간 지정
- 썸네일 프레임 선택
- 내 제목과 설명
- 감정 자막
- 연결 이유
- 원본 링크 유지
- 플랫폼이 허용하는 임베드

즉, LoveTree는 원본 콘텐츠를 소유하는 서비스가 아니라 **원본 위에 개인의 감정과 경로를 덧붙이는 서비스**다.

# 10. 플랫폼 전략

## 10.1 웹 버전

- 랜딩과 공개 트리 감상
- 전체 트리 편집
- 대형 화면의 성장 트리·그래프
- 커뮤니티 탐색
- 기획사 대시보드

## 10.2 모바일 웹

- 링크를 받고 즉시 감상
- 로그인 없이 일부 경로 체험
- URL 붙여넣기와 빠른 저장
- 앱 설치 전 핵심 경험 제공

## 10.3 모바일 앱

각 플랫폼의 공유 메뉴에서 바로 저장한다.

```text
공유 → LoveTree → 트리 선택 → 감정 → 저장
```

주요 기능:

- 공유 시트
- 푸시 알림
- 오프라인 초안
- 카메라·사진 업로드
- 음성 감정 메모
- 앱 딥링크
- 짧은 트리 재생

## 10.4 브라우저 확장 프로그램

초기 구상의 핵심 입력 장치다.

YouTube 등에서 확장 버튼을 누르면 자동으로:

- 현재 URL
- 제목
- 채널
- 재생 시점
- 선택 문장
- 현재 페이지

를 가져온다.

작은 팝업에서는 다음만 묻는다.

- 어느 트리에 넣을까요?
- 지금 어떤 마음인가요?
- 무엇 때문에 다음으로 이어졌나요?

확장 프로그램은 사용자의 몰입 흐름을 끊지 않기 때문에 LoveTree의 가장 강력한 입력 채널이 될 수 있다.

# 11. 공개 알림·추천·선택 구조

초기 구상에는 새싹 사용자가 첫 영상을 올리면 기존 사용자가 다음 영상을 추천하는 구조가 있다. 이를 다음처럼 정리한다.

## 11.1 공개 순간 알림

사용자가 공개를 선택한 경우:

- 해당 대상의 기존 팬에게 새 첫 순간 알림
- 새 영상 노드가 반짝이는 시각 효과
- 관심 태그 구독자에게 알림
- 과도한 알림을 막는 요약·빈도 설정

## 11.2 다음 영상 추천

기존 팬은 새싹의 첫 순간을 보고 다음 영상을 추천할 수 있다.

추천 카드에는:

- 영상
- 추천 구간
- 한 줄 이유
- 예상 감정
- 어느 순간 다음에 볼지

를 남긴다.

## 11.3 추천 채택

새싹은 추천을 반드시 채택할 필요가 없다.

- 추천 채택
- 나중에 보기
- 거절
- 직접 검색한 영상 선택

채택되면:

- 추천 카드와 새 순간의 색·표시 연결
- 추천자에게 알림
- 추천자의 채택 점수 상승
- 파생 경로 출처 기록

## 11.4 집단 큐레이션

여러 팬이 같은 영상을 입문 영상으로 추천하면:

- `가장 많이 심어진 첫 순간`
- `새싹이 많이 선택한 다음 영상`
- `입덕 전환이 높은 장면`

으로 집계할 수 있다.

단순 인기 영상과 실제 팬 전환 영상은 구분한다.

# 12. 커뮤니티와 공개 정원

## 12.1 공개 트리 탐색

- 대상 이름 검색
- 감정 필터

# 13. 입덕 단계·성장 단계·폴인럽 게이지

초기 구상의 `새싹·썸·폴인럽`은 유지할 가치가 있다. 다만 단순 영상 수만으로 결정하지 않는다.

## 13.1 예시 단계

### 씨앗

첫 순간을 저장하기 전 또는 첫 순간만 저장한 상태.

### 새싹

처음 몇 개의 순간과 감정을 기록한 상태.

### 썸

대상을 계속 탐색하지만 아직 완전한 입덕을 선언하지 않은 상태.

### 폴인럽

사용자가 완전히 빠졌다고 선언했거나 충분한 감정·행동 변화가 생긴 상태.

### 깊은 뿌리

장기간 꾸준히 기록하고 회상하는 상태.

### 정원

여러 코스와 커뮤니티 기여를 만든 상태.

## 13.2 게이지 구성

사용자 동의하에 다음을 참고할 수 있다.

- 저장 순간 수
- 탐색 기간
- 플랫폼 다양성
- 같은 순간 재방문
- 감정 강도 변화
- 트리 연결 밀도
- 공식 채널 구독
- 굿즈·음반·팬클럽 등 행동
- 사용자의 직접 선언

게이지는 사람의 감정을 단정하는 판정기가 아니라, **자신의 여정을 돌아보는 보조 지표**다.

## 13.3 자동과 수동의 결합

- 시스템이 “폴인럽에 가까워졌어요”라고 제안
- 사용자가 `아직 아니에요` 선택 가능
- 사용자가 언제든 `이 순간 완전히 빠졌어요` 선언
- 자동 측정 거부 가능

## 13.4 단계 이벤트

초기 구상의 예시처럼 특정 단계에서:

- 아티스트 이미지 등장
- 음성 축하 메시지
- 하트 애니메이션
- 꽃·열매 생성
- 공식 디지털 카드
- 기획사 리워드

를 제공할 수 있다.

# 17. 추천 쇼츠와 첫 순간 발굴

초기 구상에는 정국·필릭스·민지 등의 추천 쇼츠처럼, 첫 순간이 될 수 있는 짧은 영상을 보여주는 아이디어가 있다.

이를 제품화하면:

- `오늘의 첫 순간`
- `새싹이 많이 심은 쇼츠`
- `팬 전환이 높은 30초`
- `아직 트리가 적은 발견 후보`
- `내 취향과 닮은 팬이 고른 순간`

을 제공할 수 있다.

각 쇼츠에서:

- 추천
- 한 줄 평
- LoveTree에 심기
- 추천한 사용자 보기
- 해당 사용자의 전체 트리 보기
- 이 쇼츠가 어느 입덕 단계에 있는지 보기

가 가능해야 한다.

추천 피드는 무한 소비를 부추기는 일반 숏폼 피드보다 **트리로 이어지는 첫 순간 발견**에 초점을 둔다.

# 21. 탐색 시간과 측정의 원칙

초기 구상에는 하루 검색 시간, LoveTree에 올린 영상 수, 특정 콘텐츠 도달 시간, 트리 완성 시간을 측정하는 아이디어가 있다.

측정은 반드시 동의 기반이어야 한다.

## 21.1 측정 가능한 항목

- LoveTree 내부 감상 시간
- 저장 시각
- 첫 순간부터 다음 순간까지 걸린 시간
- 하루·주간 저장량
- 사용자가 연결한 플랫폼 수
- 완성 선언까지의 기간

## 21.2 확장 프로그램 측정

브라우저 전체 활동을 무단 추적하면 안 된다. 사용자가 명시적으로 켠 경우에만:

- 특정 지원 사이트에서의 사용 시간
- LoveTree에 저장한 콘텐츠
- 저장된 경로

를 측정한다.

## 21.3 사용자가 직접 완성할 자유

사용자는 세 개만 보고도 “이 정도면 완전히 빠졌다”고 선언할 수 있다. 시스템이 정한 시간이나 영상 수를 강요하지 않는다.

# 22. 팬덤 밖 확장 가능성

LoveTree의 핵심은 사람이 아니라 **처음 접한 뒤 감정·지식·행동이 변화한 경로**다. 따라서 장기적으로 여러 영역에 적용할 수 있다.

## 22.1 인물·콘텐츠

- 아이돌
- 배우
- 스포츠 선수: 오타니 등
- 유튜버·채널: 침착맨, 영화 채널 등
- 드라마
- 애니메이션
- 캐릭터
- 소설·추적물·형사물

## 22.2 구독·구매

- YouTube 채널 구독까지의 경로
- Netflix·Coupang 같은 결제 서비스 가입 경로
- 제품 구매 결정 경로
- 브랜드 팬 전환

## 22.3 여행

```text
사진 한 장
→ 장소 검색
→ 여행 영상
→ 블로그·지도
→ 숙소 비교
→ 일정
→ 예약
→ 실제 여행
```

## 22.4 공부

```text
처음 개념 접함
→ 이해 안 됨
→ 특정 강의에서 실마리
→ 문제 풀이
→ 다시 막힘
→ 다른 설명 발견
→ 성적 향상
```

## 22.5 투자

초기 구상의 투자 LoveTree:

```text
첫 브리핑
→ 꽂힌 부분
→ 추가 조사
→ 미팅
→ 회사 방문
→ 투자 결정
```

실제 투자자의 경로와 예상 투자자 경로를 비교할 수 있다.

## 22.6 첫 시장은 팬덤

범용 가능성이 있더라도 초기 메시지는 팬덤에 집중한다.

팬덤은:

- 감정 강도가 높고
- 콘텐츠 탐색이 많고
- 기록·소장 욕구가 강하며
- 공유·자랑 욕구가 있고
- 다른 팬을 만들고 싶어 하며
- 굿즈·공연·구독으로 연결되고
- 글로벌 확장이 가능하다.

팬덤에서 제품 행동을 증명한 뒤 별도 템플릿으로 확장한다.

# 23. 핵심 성장 순환

```text
발견
→ 1초 저장
→ 감정 기록
→ 추가 탐색
→ 감정의 인과관계 연결
→ 트리 성장
→ 완전한 입덕
→ 현타·휴식
→ 처음의 설렘 회상
→ 트리 공개·자랑
→ 다른 사용자가 경로 감상
→ 순간 채택
→ B의 파생 트리 생성
→ 새로운 팬 탄생
→ A에게 기여·발굴 보상
→ 더 좋은 트리와 공식 협업
```

어느 하나만 남으면 LoveTree는 다른 서비스가 된다.

- 저장만 있으면 북마크 앱
- 감정만 있으면 다이어리
- 연결만 있으면 마인드맵
- 영상만 있으면 재생목록
- 공개만 있으면 SNS
- 추천만 있으면 큐레이션 서비스
- 보상만 있으면 랭킹 커뮤니티

LoveTree는 이 모든 요소가 **사랑에 빠지는 하나의 과정 안에서 연결될 때** 독자적인 제품이 된다.

# 26. 제품 문구 원칙

LoveTree의 언어는 데이터베이스·노드·레코드보다 감정과 나무의 언어를 사용한다.

| 기능적 표현 | LoveTree 표현 |
|---|---|
| 새 레코드 | 새 순간 |
| 저장 | 심기 |
| 연결 생성 | 가지 잇기 |
| 목록 | 마음 다이어리 |
| 노드 수 | 자라난 순간 |
| 완료 | 완전히 빠진 순간 / 한 시즌 완성 |
| 일시 중지 | 나무 아래 쉬기 |
| 다시 시작 | 다시 나무로 돌아오기 |
| 추천자 | 길잡이 |
| 고기여 사용자 | 정원사·개척자 |
| 파생 복제 | 내 첫 순간으로 심기 |

단, 감성 문구가 기능 이해를 방해하지 않도록 버튼에는 명확한 동작도 함께 표시한다.

예:

- `이 순간 심기 · 저장`
- `두 순간을 가지로 잇기`
- `처음부터 다시 걷기`
- `내 첫 순간으로 심기`
- `나무 아래 잠시 쉬기`

# 27. 최종 제품 선언

LoveTree는 팬이 본 영상을 정리하는 서비스가 아니다.

LoveTree는:

- 첫눈에 마음이 멈춘 장면을 포착하고,
- 이후 찾아간 모든 길을 감정의 이유로 연결하고,
- 좋아함과 낯섦과 거부감과 설렘과 현타까지 숨기지 않고,
- 시간이 지난 뒤 처음의 감정을 다시 살려내고,
- 자신의 안목과 탐구를 한 그루의 나무로 소장하며,
- 다른 사람이 그 나무의 길을 따라 새로운 팬이 되게 하고,
- 그 팬이 다시 자기만의 나무를 키우게 만드는 서비스다.

기획사에는 공식 입덕 경로와 팬 전환 엔진이 되고, 팬에게는 사랑의 개인 아카이브와 자랑할 수 있는 작품이 되며, 새 사용자에게는 누군가를 좋아하게 되는 가장 설득력 있는 안내서가 된다.

> **사랑은 어느 한순간 시작되지만, 그 마음이 자라온 길을 기억할 때 오래 남는다. LoveTree는 그 길을 살아 있는 나무로 간직한다.**

- Step 3의 두 순간 사이 마음과 관계 이유를 핵심 데이터로 반영한다.
- 타임라인은 실제 날짜의 연혁으로 둔다.
- 사람별 앨범과 앨범 선반은 확장 보기로 둔다.
- 노드 그래프·Obsidian 방식은 고급 연결 지도에 사용한다.
- 성운은 수백·수천 개 순간의 대규모 감정 보기로 사용한다.
